# Output: test plan

Contract ledger for [the output reference](README.md). Every test spawning `sync-agents` in this
repository also validates each line it prints against its schema (`test/jsonl.ts`), so the cases
below are the dedicated ones.

| ID | Requirement | Oracle | Level | Status | Test |
| --- | --- | --- | --- | --- | --- |
| OUT-SCH-1 | `schemas/` and the registry agree, and each schema pins its own id and version | File list equals registry; `const` id and version | Unit | Implemented | `output-contract.test.ts › every file in schemas/ is a registered message schema, and every registered schema is a file` |
| OUT-SCH-2 | `--schema` prints one valid line per schema; each schema compiles | ajv compile | E2E | Implemented | `output-contract.test.ts › --schema prints one valid line per declared schema, and each printed schema compiles` |
| OUT-HLP-1 | `--help` is an `agent_hub.help` line followed by the schema of every message type, from the engine, `mcp-sync` and the wrapper | Decoded line | E2E | Implemented | `output-contract.test.ts › --help is an agent_hub.help line then every schema, from the engine, mcp-sync and the wrapper` |
| OUT-HLP-2 | The wrapper's help text is the engine's | String equality | E2E | Implemented | `output-contract.test.ts › the wrapper's help text is the engine's help text` |
| OUT-HUM-1 | `--human` / `--humanize` print prose | No JSON lines; bare path | E2E | Implemented | `output-contract.test.ts › --human prints prose, not JSON, for help, print-dir and a sync` |
| OUT-ERR-1 | A usage error is one `agent_hub.error` line, code `usage`, exit 2, empty stdout | Decoded line | E2E | Implemented | `output-contract.test.ts › a usage error is one agent_hub.error line with code usage on stderr, exit 2, nothing on stdout` |
| OUT-RUN-1 | Apply, check, dry-run, explain and conflict runs print only valid lines with one `run_id` | Decoded lines | E2E | Implemented | `output-contract.test.ts › apply, check, dry-run, explain and a conflict all print only valid lines sharing one run_id per run` |
| OUT-RUN-2 | Different runs have different `run_id`s | Inequality | E2E | Implemented | `output-contract.test.ts › two runs carry different run_ids` |
| OUT-WRP-1 | A wrapper message with control characters is still one valid line | Round-trip | E2E | Implemented | `output-contract.test.ts › a wrapper message with control characters is still one valid JSON line` |
| OUT-RUN-3 | Output larger than a pipe buffer reaches a slow reader whole | All lines decode; more than 400 `op` lines | E2E | Implemented | `output-contract.test.ts › output larger than a pipe buffer reaches a slow reader whole, from the engine and the wrapper` |
| OUT-RUN-4 | Every run past parsing ends with one `summary` or `error` line | Terminal count; `planned` on dry-run | E2E | Implemented | `output-contract.test.ts › every run past argument parsing ends with one summary or error line: dry-run with changes, explain, check` |
| OUT-RUN-5 | In-process runs (recovery, locks, apply failure) meet the same contract: valid events, messages equal to events, one terminal event last | Every `runSync` in the suite goes through `test/jsonl.ts`; read-only recovery modes report `pending` / `ambiguous` | Unit | Implemented | `recovery.test.ts › ambiguous target modified unexpectedly after interruption -> preserves destination & journal, blocks next run` |
| OUT-ERR-2 | An uncaught throw becomes one `internal` error line | Decoded line; exit 1 (in-process, so it holds on every platform) | Unit | Implemented | `output-contract.test.ts › an uncaught throw in the engine becomes one agent_hub.error line with code internal, exit 1` |
| OUT-ERR-3 | A child process's stderr arrives inside an error line | Decoded `error` naming `tar` / `unzip` | E2E | Implemented | `output-contract.test.ts › a child process's stderr (tar, unzip) arrives inside a valid error line, never as raw text` |
| OUT-ERR-4 | A wrapper `--print-dir` that cannot resolve the hub is one error line, exit 1 | Decoded line; empty stdout | E2E | Implemented | `output-contract.test.ts › a wrapper --print-dir that cannot resolve the hub is one error line, exit 1, nothing on stdout` |
| OUT-HUM-2 | `--humanize` in the engine; an option value spelled `--human` is not the flag | Bare path; JSON with a `--human` path | E2E | Implemented | `output-contract.test.ts › --humanize works in the engine as in the wrapper, and an option value spelled --human is not the flag` |
| OUT-SCH-3 | `--schema` wins over `--help` and `--print-dir` in both entrypoints | Only `schema` lines | E2E | Implemented | `output-contract.test.ts › --schema wins over --help and --print-dir in the wrapper as in the engine` |
| OUT-BIN-1 | The compiled binary prints the same contract, schemas embedded | Every binary run in the suite decodes | E2E | Implemented | `binary.test.ts › --help prints the CLI usage and exits 0; usage errors exit 2` |
| OUT-RUN-6 | No test bypasses the checked `runSync` | No test file imports `runSync` from `src/cli.ts` | Unit | Implemented | `output-contract.test.ts › no test calls src/cli.ts runSync directly; in-process runs go through the checked runSync` |
| OUT-RUN-7 | A reader that closes the pipe early gets exit 0 and no crash text | `PIPESTATUS[0]` 0; empty stderr | E2E | Implemented | `output-contract.test.ts › a reader that closes the pipe early (head -1) gets a clean exit 0 and no crash text` |
| OUT-RUN-8 | `applied` counts the changes applied | `changes` equals the `sync` op lines (also asserted on every in-process run) | E2E | Implemented | `output-contract.test.ts › an applied summary counts the changes applied, not the targets written` |
| OUT-ERR-5 | Explain with changes ends `planned`; a missing hub is `hub_not_found`; a newline path is `config` | Decoded terminal lines | E2E | Implemented | `output-contract.test.ts › explain with changes ends planned; a missing hub is hub_not_found; a newline path is a config error` |
| OUT-HUM-3 | The wrapper treats every option's value as a value | Same exit as the engine; no help or print-dir line | E2E | Implemented | `output-contract.test.ts › the wrapper treats every option's value as a value, as the engine does` |
| OUT-ERR-6 | A write failure other than a closed pipe is an `internal` error line on the other stream, exit 1 | stdout opened read-only; decoded stderr | E2E | Implemented | `output-contract.test.ts › a write failure other than a closed pipe is an error line on the other stream and exit 1, not a crash` |
